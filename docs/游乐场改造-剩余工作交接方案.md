## 二、步 4:空态说明书

### 目标

主区空态从通用引导词改成**选中模型的说明书**。用户点了模型就该看到这个模型能干什么、怎么用、有什么坑,而不是四个和模型无关的示例按钮。

### 现状

`components/chat/playground-empty-state.tsx` 目前是固定内容:一个图标 + 标题"Start a playground chat" + 四个 starter prompt 按钮(Analyze data / Summarize text / Code / Get advice)。完全不感知当前选中的是哪个模型。

### 要做的事

**1. 新增内容注册表** `lib/capability/model-guide.ts`

按 modality 提供说明书内容。结构建议:

```ts
export type ModelGuide = {
  /** 一句话定位,显示在模型名下方 */
  tagline: string
  /** 3-4 条"适合做什么" */
  strengths: string[]
  /** 2-3 条已知限制或坑点,这是与竞品拉开差距的部分 */
  caveats?: string[]
  /** 可点击直接填入编辑器的示例,替换现有 starterPrompts */
  examples: Array<{ icon: string; label: string; prompt: string }>

```

按 modality 兜底,模型级覆盖可选(`Record<PlaygroundModality, ModelGuide>` 加一个 `Partial<Record<string, Partial<ModelGuide>>>` 按模型名覆盖)。**不要**为每个模型手写一份,维护不起。

**2. 新增组件** `components/chat/model-guide-panel.tsx`

## 三、步 5:参数芯片条

### 目标

编辑器底部一行内联芯片,每个芯片**常驻显示当前值**,点击弹出选项。用户不打开面板就能看到自己的配置。

### 现状

`components/input/playground-input-controls.tsx` 底部目前是 `ModelGroupSelector` + 工具按钮 + 发送按钮。参数在 `playground-parameter-panel.tsx` 里,是一个折叠面板,里面按 `PLAYGROUND_PARAMETER_CONTROLS`(temperature / top_p / frequency_penalty / presence_penalty / max_tokens / seed)渲染滑块和数字输入。

### 要做的事

**1. 新增组件** `components/input/param-chip.tsx`

单个芯片。数据来自 `ParamChipSpec`(已定义在 `lib/capability/types.ts`):

```ts
type ParamChipSpec = {
  id: string
  icon: string          // Lucide 图标名,组件内解析
  label: string
  description?: string  // 弹层顶部说明段
  options?: ParamOption[]
  customInput?: boolean // 选项下方额外渲染自由输入 + 确认按钮
}
```

芯片外观:`h-7 rounded-full`,图标 + `label` + 当前值。有非默认值时用 `border-primary/45 bg-accent`(与左栏 tab 一致),默认值时用无边框弱化态。

弹层用 `Popover`。顶部 `description` 段落,下面选项列表(选中项打勾),`hint` 作为选项副行。`customInput === true` 时底部加输入框 + 确认按钮。

**注意 `icon` 是字符串**,需要一个 Lucide 名称 → 组件的映射。项目里已有 `getLobeIcon` 处理厂商图标,但那是另一套(lobehub),Lucide 图标要另建映射表。**不要用动态 import 或 `eval`**,建一个显式 `Record<string, LucideIcon>`,只登记 registry 里实际用到的那些(Route / Layers / RectangleHorizontal / Sparkles / Monitor / Clock / Gauge / Smile / SlidersHorizontal / Type / Images / Brush / Combine)。

**2. 新增容器** `components/input/param-chip-bar.tsx`

按 `capability.params` 顺序渲染芯片。`advanced` 这个特殊芯片(chat 模态里)应该打开现有的 `playground-parameter-panel.tsx`,而不是渲染成普通选项弹层 —— 那 6 个采样参数是滑块,不是离散选项。

**3. 状态管理(含持久化,别漏)**

芯片值需要新的状态槽。`hooks/use-playground-state.ts` 里已有 `config` 和 `parameterEnabled`,建议加 `paramChipValues: Record<string, string>` 并提供 `updateParamChip`。

**关键:这两个既有状态都是持久化的,不是纯内存 state。** 照抄 `updateConfig` 的模式(`hooks/use-playground-state.ts:112-121`):

```ts
const updateConfig = useCallback((key, value) => {
  setConfig((prev) => {
    const updated = { ...prev, [key]: value }
    saveConfig(updated)      // ← 每次更新都写 localStorage
    return updated
  })
}, [])
```

所以加芯片状态要一并处理这条链路:

1. **`constants.ts` 的 `STORAGE_KEYS`** 加一个键。现有三个:`CONFIG: 'playground_config'`、`MESSAGES: 'playground_messages'`、`PARAMETER_ENABLED: 'playground_parameter_enabled'`。按同样命名加 `PARAM_CHIPS: 'playground_param_chips'`
2. **`lib/storage/storage-schema.ts` 加 Zod schema**。读取时是校验过的,不是裸 `JSON.parse` —— 不写 schema 会在读取处失败
3. **`lib/storage/storage.ts` 加 `loadParamChips` / `saveParamChips`**,照 `loadConfig`/`saveConfig`(第 331、345 行)和 `loadParameterEnabled`/`saveParameterEnabled`(第 360、374 行)的写法
4. **注意 `STORAGE_VERSION`**(`storage-schema.ts:21`,当前为 `1`)。新增独立 key 且旧数据缺失时能优雅回退到默认值,就不用动版本号;**如果改了任何既有 schema 的形状,必须升版本**,否则老用户的 localStorage 数据会校验失败

**或者:明确决定芯片值不持久化。** 也是合理选择(刷新回默认反而更可预期)。但要在代码注释里写明是有意为之,否则会被当成漏实现。

**芯片值目前不需要进请求体** —— 除了 chat 的 `advanced`,其他模态的 relay 路由都还没开放(`available: false`),芯片是纯 UI。请求体拼装留到各模态实际接通时做。这一点务必在代码注释里写清楚,否则接手的人会以为漏了。

**4. 接入**

`playground-input-controls.tsx` 在 `renderSelector()` 那一行下方插入 `ParamChipBar`。当前 modality 由 `index.tsx` 传下来的选中模型推导:`model.modality ? getCapability(model.modality) : undefined`,无 modality 时不渲染芯片条。

### 无障碍:交互元素的既有约定

前 3 步的组件都做了这几件事,新组件请保持:

- 自定义按钮用 `aria-pressed={isSelected}` 表达选中态(模型卡、模态 tab 都是)。**不要用 `aria-current`** —— 那是给导航项的,选择器用 `aria-pressed`
- 焦点环:`focus-visible:ring-ring/50 outline-none focus-visible:ring-3`(卡片)或 `focus-visible:ring-2`(小控件),不要只靠 hover 态
- 截断的文本加 `title` 属性,否则长模型名在窄栏里无法读全
- 纯装饰元素加 `aria-hidden`
- 选中态不能只靠颜色。模型卡用了 `border-primary/45` + `bg-accent` + `shadow-sm` 三重信号,灰度下仍可辨

## 五、建议执行顺序

先步 4 再步 5。理由:步 4 是纯内容展示,不碰状态管理,风险最低;步 5 要往 `use-playground-state.ts` 加状态槽,牵动面更大。两步都不阻塞对方,但步 4 做完能先看到明显的产品价值。

**动手前先定 i18n 路线(三点五节)。** 这个决策影响两步的工作量,事后返工代价高。

每步完成后在 `web/` 目录下跑全套:

```
npx tsc --noEmit -p tsconfig.json
npm run lint
npx vitest run --config vitest.node.config.ts
npm run format
npm run build
```

几点说明:

- `npm run lint` 跑的是 oxlint,**会输出仓库里既有的其他告警**。只看自己文件的,可以 `| grep -iE "playground|model-library"`
- 我踩过的两个 oxlint 规则:`no-duplicate-imports`(同一模块的值和类型要合并成一条 `import { X, type Y }`)和 `no-nested-ternary`(嵌套三元要抽成子组件或早返回)
- `npm run format` 之后记得 `git checkout -- web/scripts/`
- **`npm run build` 别省** —— 布局改动有过只在构建期暴露的问题,tsc 干净不等于构建通过。这一步约 1-2 分钟
