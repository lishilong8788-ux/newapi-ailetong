优先级 vs 权重

配渠道时最常被搞反的两个旋钮。选错的后果：你以为在灰度放量，其实是全量切换。

1一句话区分

两个旋钮解决完全不同的问题，不能互换

🔢 优先级 Priority

硬性分层 · 高的活着，低的永远轮不到
= 主备关系（容灾）
系统只在最高优先级那一层里挑。
优先级 10 的渠道还活着 → 优先级 5 的一次都不会用。
只有高层全部失败重试时，才降级到下一层。
官方直连设 10，中转设 5
→ 平时全走官方，官方挂了自动降级

⚖️ 权重 Weight

同层内加权随机 · 按比例分流量
= 流量分配（放量）
在同一优先级的渠道之间，按权重比例随机。
三个渠道权重 100/50/50 → 大约 50% / 25% / 25%。
每个请求独立随机，不是轮询。
想让新渠道试水 10% 流量
→ 调权重，不是优先级
最常见的错误：想做灰度（10% 流量导到新渠道试水）， 结果去调优先级 —— 那不是放量，那是全量切换。
新渠道优先级设高一点，老渠道就一个请求都收不到了。
放量用权重，容灾用优先级。

2先看分层：优先级怎么工作

这是「只在最高层挑」的直观呈现
正在服务优先级 10
官方直连A 60%60%
官方直连B 40%40%
闲置优先级 5
中转甲 0%
中转乙 0%
优先级 5 那一层一个请求都收不到，哪怕它权重设得再高。
只有优先级 10 全部失败、进入重试时，才会降级到这一层 —— 这就是「主备」。

3自己动手：改权重看流量分配

重点试预设里的「权重 1 和 0」，那个结果会让你意外

4权重的隐藏规则（生产环境实际算法）

这块有坑，而且开不开内存缓存算法不一样
生产环境默认开内存缓存（MEMORY_CACHE_ENABLED=true），走的是带平滑的算法：
情况① 所有渠道权重都是 0 　　→ 每个渠道有效权重都算 100 → 完全均分 情况② 平均权重 < 10（比如 5/3/2） 　　→ 所有权重 ×100 放大 → 比例不变，但不做补偿 情况③ 平均权重 ≥ 10（比如 100/50/50） 　　→ 直接按权重比例分配
致命细节：情况② 里权重 0 的渠道会拿到 0% 流量，彻底饿死。
例：两个渠道权重 1 和 0 → 平均 0.5 < 10 → 走情况②
→ 有效权重变成 100 和 0 → 权重 0 那个渠道永远收不到请求。

但如果两个都是 0，反而走情况①，变成各 50%。
所以「全 0」和「1 和 0」的结果完全相反 —— 这是最反直觉的一点。
实操建议：要么全都不填权重（均分），要么全都填上且都 ≥ 10。
最忌讳的是「只给一部分渠道填权重，剩下的留 0」—— 留 0 的那些会静默饿死， 你会以为它们在分担流量，实际一个请求都没走。

5降级是怎么触发的

优先级分层要真正起作用，得靠重试机制
第 1 次尝试 → 在最高优先级层里按权重挑一个 　　失败（429 / 5xx / 超时）↓ 第 2 次尝试 → 降到次高优先级层 　　还失败 ↓ 第 3 次尝试 → 再降一层…… 重试次数用完 → 返回错误给客户
所以优先级层数不宜超过 3 层 —— 层数比重试次数还多的话，最底层永远轮不到。
哪些错误会触发降级： 429 限流、5xx 上游故障、307 重定向、连接超时。
哪些不会（直接返回客户）： 400 参数错误（客户请求本身有问题，换渠道也一样错）、408 超时、余额不足等本地错误。

6后台在哪配

两个字段在同一个页面
渠道 → 编辑某渠道 → 优先级　/　权重
两个都是数字输入框，默认都是 0。
全部渠道都用默认值 0 时 → 同一层 + 完全均分，这是最简单也最安全的起点。
改完记得等配置同步（最多 60 秒）。 优先级和权重存在渠道路由表里，改动要等缓存刷新才对所有节点生效。
改完立刻测发现没变，先等一分钟。

7四个典型配置

目标怎么配为什么
最简起步 所有渠道优先级和权重都留 0 同层均分，不用想太多
主备容灾 官方直连 优先级 10　中转 优先级 5
权重都留 0		 平时只走官方，挂了自动降级到中转
灰度放量 优先级都设同一个值（如都 10）
老渠道权重 90，新渠道权重 10		 新渠道拿 10% 流量试水；观察没问题再逐步调高
按容量分流 优先级都相同
权重按各家能承受的 QPS 比例填，都 ≥ 10		 大容量的多接活，避免小渠道被打爆
灰度放量的正确节奏： 10% → 观察一天 → 30% → 观察 → 50% → 全量。
每次只调权重，优先级始终保持相同。一旦发现新渠道有问题，把权重调回 0 就行（但记得此时另一个渠道权重要 ≥ 10，否则触发前面说的饿死规则会导致比例异常）。

8怎么验证真的生效了

配完别靠猜，用日志验证：
日志 → 消费日志 → 看「渠道」列的分布
发 20~50 个请求，统计各渠道出现的次数，和你配的权重比例对一下。
样本要够：权重是每次独立随机的，发 5 个请求可能全落在同一个渠道，那是正常的随机波动，不是配置没生效。
🎯 如果只记三件事
1. 优先级 = 主备容灾（高的活低的死）　权重 = 灰度放量（同层按比例）
2. 灰度放量要把优先级设成相同值，再调权重。调优先级 = 全量切换
3. 要么权重全留 0，要么全填且都 ≥ 10。混着填会让留 0 的渠道静默饿死
