分组配置流程模拟器

同一个名字，要在四个地方对上号 — 漏一个就会看到对应的报错

先看懂这一件事

分组不是一个"东西"，是一个名字。这个名字要在四个不同的地方各写一次，四处都对上，流量才通、价格才对。

分组倍率     "tx3": 0.5           ← 值多少钱（也决定渠道下拉框能不能选到）
用户可用分组 "tx3": "公有云·tx3"   ← 谁能用、显示成什么
渠道的分组   tx3                   ← 流量去哪台机器
令牌的分组   tx3                   ← 这把钥匙走哪条路

下面四个勾，你可以随意勾/不勾，看漏掉某步会发生什么。

① 把四步勾一遍

1
在「分组倍率」里注册并定价
系统设置 → 分组与模型定价设置
决定这个分组值多少钱。也是渠道下拉框选项的唯一来源。
2
在「用户可用分组」里登记
系统设置 → 用户可用分组
决定客户能不能用它、在令牌下拉框里显示成什么中文名。
3
渠道的「分组」字段挂上这个名字
渠道 → 编辑 → 模型与分组
决定流量真正落到哪台上游。没有这步，请求会报「无可用渠道」。
4
令牌的「令牌分组」选这个名字
令牌 → 新建/编辑
不选就走用户自己的分组，享受不到这个价格。

② 两个下拉框现在长什么样

这两个框读的是不同的配置，这就是你「渠道能看到、令牌看不到」的原因。

渠道 → 分组
数据来源：分组倍率的所有键
令牌 → 令牌分组
数据来源：分组倍率 ∩ 用户可用分组

改完必须刷新页面。渠道编辑页的下拉框选项是打开页面那一刻拉取的，不会自动更新。很多人配完回到渠道页发现还是选不到，以为没生效，其实只是没刷新。

为什么渠道那个框不让手填

你截图里打 11111 显示「没有匹配项」—— 这不是 bug。同一个页面上，模型那个框是允许自己造名字的，代码里差一个开关：

// 模型框 —— 允许自定义
<MultiSelect options={modelOptions} allowCreate />   ← 有

// 分组框 —— 只能挑
<MultiSelect options={groupOptions} />               ← 没有

挡住你是有道理的：如果能在渠道页随手造一个分组名，这个分组就成了孤儿 —— 没有倍率、没人有权限用、流量永远进不来。你会得到一个看起来配好了、实际永远不工作的渠道。

一个容易踩的例外

用户自己所属的那个分组，永远可用，不需要在「用户可用分组」里登记。

所以如果你把某个用户的分组直接改成 tx3，他不需要第②步就能用。但别靠这个偷懒 —— 这样一来令牌下拉框还是空的，客户没法自己选，而且你也没法把这个分组开放给其他用户。

如果你要复刻多渠道差异定价

把上面四步对每个上游各做一遍，分组名不同、倍率不同即可。不需要改任何后端代码。

分组倍率：
{
  "default": 1,
  "ai15": 0.5,     ← 官转，5折
  "tx3":  0.5,     ← 公有云腾讯，5折
  "jd6":  0.79,    ← 公有云京东，7.9折
  "op1":  1.09     ← 企业中转，加价9%
}

然后 4 个渠道各自挂一个分组名，
模型列表填一模一样的模型名。
唯一做不到的事：分组倍率是一个数，输入和输出被同一个数缩放。如果某个上游的真实结构不同（比如输出是输入的 8 倍，而你按 3 倍配），那部分会亏钱。

绕法：给它单独起一个模型名单独定价，再在渠道上用模型重定向把名字改回上游认识的真名。代价是客户会看到两个型号。

只记三件事

1. 渠道下拉框的选项，只来自「分组倍率」。选不到就是那里没注册。

2. 令牌下拉框要过两道筛选，分组倍率和用户可用分组都得有。

3. 改完配置要刷新页面，否则下拉框还是旧的。
