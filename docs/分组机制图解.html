分组机制图解

先看类比 → 自己动手点 → 再看配置位置。别按顺序死读，直接玩第 2 节那个模拟器最快。

1一句话理解

分组不是两种东西，是同一个标签贴在三个地方
分组就是套餐标签。
贴在渠道上 = 这条线路服务哪些套餐；贴在用户上 = 他买的是哪个套餐； 贴在令牌上 = 这把钥匙强制走哪个套餐（不填就跟随用户）。

🏭 供给侧：渠道打标签

defaultvip → 廉价中转（便宜、偶尔抽风）
vipsvip → 官方直连（贵、稳定）
经济组 → 超廉价池（很便宜、慢）
含义：这条线路愿意服务哪些套餐的人

👤 需求侧：用户和令牌

用户张三 vip ← 他的身份档位
├ 令牌A 留空 → 跟随 vip
├ 令牌B 经济组 → 强制走经济组
└ 令牌C svip → ❌ 无权，403
含义：令牌覆盖用户，但不能越权
只记这一条公式： 最终分组 = 令牌分组填了就用它，没填就用用户分组。
其他所有复杂度，都是围绕这一行加的安全检查和价格计算。

2自己动手：点一下看会发生什么

左边选身份，右边选钥匙，点按钮看请求怎么走。多试几种组合，尤其是被拦下的那些

3为什么要两层？

如果只有用户分组，下面这些都做不到
场景怎么配价值
企业多项目隔离
最主流用法		 令牌分组全部留空，靠令牌独立额度隔离：客服机器人 500 元、内容生成 2000 元、测试 50 元 一个项目跑飞不会烧光公司余额
同客户分质量档 生产环境令牌留空（走 vip 优质池），测试环境令牌填 经济组 测试省钱，生产保稳
你自己内测新渠道 新渠道只打 内测组 标签，给自己发个 内测组 令牌 不影响任何真实客户
给客户灰度 不动用户分组，只发一个新组的令牌给他试；出问题停用这个令牌即可 令牌是可抛弃的实验单元
纠正一个常见误解：令牌分组不是必填项，留空才是常态。 大部分令牌都该留空。填了之后你就多了一处要同步维护的地方 —— 用户升级到 vip 了， 但那个写死 default 的老令牌还在走 default，客户会来投诉「我充了钱怎么没变快」。

4后台在哪配：五个位置

顺序很重要，反了会报错。按 1→5 配
1. 先建倍率（不然后面全报「分组已弃用」）
系统设置 → 分组与模型定价 → 分组倍率
填 {"default":1.0, "vip":0.9, "经济组":0.5}　有可视化编辑器，不用手写 JSON
2. 给渠道打标签（不然报「无可用渠道」）
渠道 → 编辑某渠道 → 分组 字段
多选。含义是「这条线路向哪些分组开放」
3. 放进用户可选名单（不然用户在下拉框里选不到）
系统设置 → 分组与模型定价 → 用户可选分组
填 {"经济组":"经济模式（较慢）"}　右边的描述是给终端客户看的，别写内部术语
4. 分配用户档位
用户 → 编辑某用户 → 分组 字段
支持筛选后批量改，不用一个个点
5.（可选）需要覆盖时才填令牌分组
令牌 → 编辑 → 分组　｜　客户自己：个人面板 → API 令牌
客户能选到的选项 = 第 3 步那份名单
两个高危操作：
① 删掉某分组的倍率 = 立刻停用该分组，所有绑定它的令牌马上 403。下线套餐前先确认没有活跃令牌在用。
② 分组名不要改名。它是当字符串在渠道、用户、令牌、三张倍率表里到处引用的，改名不会级联更新，等于同时废掉一批配置。要换名字：新建 → 迁移 → 再删旧的。

5auto 分组：自动降本

特殊分组名，行为和普通分组完全不同
普通分组 = 锁定一个渠道池。auto = 按你排的顺序依次尝试多个分组。
令牌分组 = auto，顺序 = [经济组, default, 直连组] 请求来 → 先在「经济组」找 → 有 → 用它，按经济组 0.5 倍收费 经济组全挂 → 试「default」 → 有 → 按 1.0 倍收费 还不行 → 试「直连组」 → 按 1.5 倍收费
产品含义：自动省钱 + 自动容灾。平时走最便宜的，挂了自动升级，客户无感。
计费按实际命中的组算，所以同一个令牌的单价会浮动。 如果客户是按固定单价谈的合同，别给他 auto 令牌，否则对不上账。
另：默认一个令牌最多配 5 个 auto 分组，可在系统设置里调。限制是防止一个请求把十几个组全试一遍，把响应时间拖到几十秒。

6出问题怎么查

四种报错各自对应哪一边没配好
报错 / 症状缺哪一边去哪修
当前分组下没有可用渠道供给侧缺失：没有任何渠道打了这个分组标签，或打了但没启用该模型渠道 → 分组字段
无权访问 xxx 分组权限闸门拦下：这个分组不在该用户的可选名单里系统设置 → 用户可选分组
分组 xxx 已被弃用倍率没配：分组倍率表里查不到这个分组系统设置 → 分组倍率
能用但价格不对倍率配错，或被「用户分组专属倍率」覆盖了查消费日志的倍率列
改了配置没生效不是 bug：配置同步周期最多 60 秒等一分钟再复测
唯一可信的验证方式是看消费日志。 日志里记录了本次请求实际使用的分组和各项倍率 —— 比你在配置页上看到的更真实， 因为它反映了完整的解析结果（含令牌覆盖、auto 降级）。

7上线前必测

第 3 条是安全测试，别跳过
☐ 普通令牌（分组留空）能调通 → 日志里分组 = 用户分组
☐ 指定分组的令牌能调通 → 日志里分组 = 令牌分组，倍率正确
☐ 越权测试：令牌填一个该用户无权访问的分组 → 必须 403，不能放行
☐ 删掉某分组倍率 → 绑定它的令牌立刻报「已弃用」（确认停用机制有效）
第 3 条失效意味着客户能自己白嫖低价分组。 他只要猜到你的低价分组名，填进自己的令牌就能用 —— 这道闸门是拦这个的。
🎯 如果只记三件事
1. 令牌分组默认留空，只在「同一客户要多档位」时才填
2. 三边要对齐：渠道打了标签 + 分组配了倍率 + 用户名单里有它
3. 分组总数控制在 5 个以内，超过就该考虑用别的机制（令牌额度、模型重定向）解决
